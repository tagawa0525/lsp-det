# ADR 0009: 成功基準を「仕様・準拠テスト・参照実装の自己無矛盾」に置き換え、lsp-det を上流側と下流側の参照実装として再定義する

- 日付: 2026-09-02
- 状態: 採用
- 関連: [ADR 0001](0001-tool-first-readiness-gate.md)、[ADR 0002](0002-extension-b-surface-in-v01.md)、[ADR 0003](0003-extension-s-zero-based.md)、[ADR 0004](0004-spec-grilling.md)、[ADR 0008](0008-unknown-readiness-and-health-terminates-waiting.md)。本 ADR が置き換える決定は末尾の表に列挙する

## 経緯

方針の精査（2026-09-02）で、ADR 0001 決定 1 の成功基準「自分の環境で便利に使えること」が本プロジェクトの目的と一致していないことを確認した。目的は LSP に欠けている「サーバー状態」の語彙を埋めることであり、自分の環境で便利かどうかはその手段の一つにすぎない。この基準のずれから、次の歪みが生じていた。

- 非常口タイムアウト（設計 4.4、既定 300 秒）に根拠がなく、発動時に保留分をそのまま転送するため、消すはずの「無言の嘘」に戻る経路が設計の中に残っていた
- `--gate-mode` の既定を Claude Code のエラー表示の実測で決めるとしており、仕様の意味論ではなく一クライアントの UI に判断を委ねていた
- 設計 1 章が利用者に Serena を掲げる一方、v0.1 の範囲では Serena 経路に効果がなかった（rust-analyzer は Serena が自前で待ち、gopls は M4 送り）
- M1 の定義（Claude Code プラグインとしての日常稼働）を満たさないまま完了扱いになっていた
- 「拡張 S」「保証グレード」といった造語が増え、内容から判断できない語で文書が書かれていた

あわせて、仕様が中継層の都合で膨らんでいる点も確認した。`dead` と両軸の `unknown` は「サーバーが送出してはならない値」であり、上流提案の場では削られる前提の値が本文に 3 つ並んでいた。

## 決定

### A. 目的と成功基準

1. 目的は LSP に欠けている「サーバー状態」の語彙を埋めることである。ADR 0001 決定 1 の「成功基準は自分で便利に使えること」を廃止する
2. v0.1 の成功基準は次のとおり。**サーバー状態プロトコルの仕様、上流側と下流側それぞれの準拠テスト、両半身の参照実装が自己無矛盾で、rust-analyzer と gopls に当てて通ること**。「1 ヶ月の安定稼働」のような時間条件は置かない
3. 実サーバーへのネイティブ実装、クライアントの採用、LSP 本体への提案は成功基準に含めず、順序付きの次段階として扱う
4. 自分の環境（Claude Code）での稼働は成功基準ではなく、準拠テストが見落とす実サーバーの挙動を拾う観測手段として続ける。観測結果は research に記録し、仕様 8 章の根拠にする
5. 埋める穴の範囲は readiness・health・freshness の 3 側面（ADR 0003 決定 1 のまま）。診断の完了は予約のみ（ADR 0003 決定 4 のまま）

### B. 用語

1. 「拡張 S」を廃止し、**サーバー状態プロトコル**（英語では serverState）と呼ぶ。「拡張」は LSP 側の位置づけ（`experimental/` 配下の拡張）を言うときだけ使う
2. 「保証グレード」を廃止する。`completeness` / `freshness` は LSP の慣行（`renameProvider: boolean | { prepareProvider }` 等）どおり capability のオプションであり、**保証**と呼ぶ
3. lsp-det の 2 つの半身を**上流側**（言語サーバーを代行する）と**下流側**（クライアントを代行する）と呼ぶ。代行・ゲート・写像（アダプタ）は内容どおりの語なので使ってよい
4. 凍結中の 2 つ（旧「拡張 A」の宣言範囲、旧「拡張 C」の起動方法の宣言）は、解凍時に中身と一緒に名前を決め直す。本 ADR では決めない

### C. 仕様の構造

1. 仕様を**サーバーの義務**と**観測者が合成する値**の 2 層に分ける。後者を削っても前者が成立する形にする。上流提案の場では前者だけが読まれる前提で書く
2. 「観測者」は中継層に限らない。接続やプロセスを外から見られる主体すべて（プロキシ、クライアントライブラリ、エディタ本体）を含め、中継層はその一例とする。仕様 6.1 末尾の「提案時に再検討する」留保はこれで解消する
3. **`health: dead` をワイヤから外す**。ADR 0003 決定 2 を廃止する。理由は「却下した案」を参照
4. **時間に基づく判定を仕様から排除する**。状態は信号（通知・プロセス消失）だけで決まる。`experimental/serverState` リクエストは問い合わせ時点の状態を即答し、応答がないときの解釈（死んだとみなす等）はクライアントの権利であって仕様は定めない
5. 仕様 7.1 の 1「initialize 直後の `readiness` は `ready` ではない」を要件から外し、「fixture はインデックスに観測可能な時間を要する規模」をテストの前提条件として書く。小規模ワークスペースで正直に `ready` を返すサーバーを落とさないため
6. 仕様に非規範の章「クライアントの推奨挙動」を置く。内容は「`readiness` が `ready` でなく `health` が `error` でなければ横断リクエスト（7.0 の列挙）を待つ。`health` が `error` なら即座に失敗する。`readiness` が `unknown` なら進む」。仕様 1 章「クライアントの挙動を強制しない」は非規範にすることで守る

### D. lsp-det の構造

1. lsp-det は**常に両半身で動く**。LSP の境界を lsp-det の中央に置き、境界の上では常にサーバー状態プロトコルに準拠したやり取りが流れる。上流側は上流を準拠に見せ、下流側は準拠クライアントとして振る舞い下流を代行する。「透過」（ADR 0008 追補 D）は独立した概念ではなく、上流が自ら宣言していれば上流側が恒等写像になる、という一形態に還元する
2. 上流側は上流の `InitializeResult.serverInfo.name` で写像を選ぶ。rust-analyzer も gopls も自分の名前と版を名乗る（`session.rs`、`general.go` で確認）。サーバーが自ら名乗るプロトコル上の事実なので、ADR 0001 決定 6 が退けた「暗黙の探索」には当たらない。名乗りがない、または未知の名前なら写像なしで両軸 `unknown`
3. 写像に必要な capability（`window.workDoneProgress`、`experimental.serverStatusNotification`）は、`serverInfo` が分かる前に上流へ `initialize` を送る必要があるため、既知の写像ぶんを**無条件に注入する**。どちらも「通知を送ってよい」という許可にすぎず、副作用はない
4. 旧来の通知（rust-analyzer の `experimental/serverStatus` 等）は原文のまま下流へ流す（ADR 0006 決定 4 のまま）
5. 上流側の保証宣言は、**準拠テストを通した言語サーバーの版の範囲**でのみ出す。写像がその範囲を持ち、`serverInfo.version` が範囲外なら `completeness` / `freshness` を宣言しない。lsp-det は言語サーバーの内部を保証できず、観測しか持たないため
6. 写像は言語サーバーの語彙の粗さを補う責任を持つ。rust-analyzer の `warning` のうち「ワークスペース未発見」は横断問い合わせにとって機能不全なので `error` に写す。下流側の参照挙動は仕様の値だけを見て決める
7. 下流側は決定 C-6 の推奨挙動の参照実装である。待つのは仕様 7.0 の 11 メソッドだけで、1 ファイル系（hover、completion、documentSymbol 等）は `indexing` 中も通す。下流が `experimental.serverState` を宣言していれば状態を転送するだけで待たない（ADR 0002 決定 3 のまま）。宣言したクライアントが待たないのは、そのクライアントに足りないものであって、lsp-det が隠すものではないので、上書きフラグは持たない
8. 下流側にも準拠テストスイートを持つ。準拠した偽上流を立て、lsp-det をクライアントとして被験者にし、「`ready` まで待つ」「`error` で即失敗」「`unknown` で進む」を検証する。将来 Claude Code や Serena がネイティブ対応したとき、同じスイートで被験者を差し替える
9. 上流の消失時は、保留分にエラーを応答し、下流に stdio の EOF を見せて終了する。`shutdown` を受けたときも保留分にエラーを応答してから上流へ流す。応答を返さないリクエストを作らない。`$/cancelRequest` の扱い（設計 4.4）は変えない
10. **時間の非常口を持たない**。設計 4.4 を廃止する。ハングの検知は外側の実クライアントの責任
11. CLI は `lsp-det -- <上流コマンド>` のみ。`--adapter`（決定 D-2 で不要）、`--gate-timeout`（D-10）、`--gate-mode`（C-6 で既定が仕様から決まる）、`--no-gate`（D-1 で両半身常時稼働）を削除する
12. 宣言していないクライアントへの「不完全かもしれない」通知は作らない。境界の上では上流側が `readiness: indexing` を下流側に渡しており、それをどう扱うかは下流側が参照実装として示す

### E. 進め方

1. 文書を先に直す。順序は本 ADR → ADR の索引と状態行 → 仕様の 2 層化と `dead` 削除 → 設計の書き換え → CLAUDE.md
2. 実装は下流側と下流側の準拠スイート、最後に gopls の写像
3. gopls を v0.1 に含める理由は「作者の使用言語」ではなく、**既存信号を写すだけでない写像が 1 つ要る**（サーバー本体に信号がない言語にも示す）ことに置き換える
4. 覆した ADR は本文を変えず、状態行に「廃止（ADR 0009 が置き換え）」と対象の決定番号を書く。`docs/adr/README.md` に索引を置き、各 ADR について生きている決定を 1 行で列挙する

## 影響

### 仕様（docs/spec/extension-s-server-state.md）

- 「拡張 S」を「サーバー状態プロトコル」に改める。ファイル名は別途決める
- 本文を「サーバーの義務」と「観測者が合成する値」に分ける。6.1 の送出主体の表は後者の章へ移す
- 3 章・6.1・8 章から `dead` を削除する
- 6.1 末尾の「提案時に再検討」の留保を、観測者の一般化（C-2）に置き換える
- 5.1 の「グレード」を「保証」に改める
- 7.1 の 1 を要件から外し、fixture の規模を前提条件として書く（C-5）
- 非規範の章「クライアントの推奨挙動」を追加する（C-6）。あわせて下流側の準拠要件を 7 章に追加する（D-8）

### 設計（docs/v0.1-design.md）

- 1 章: 成功基準を A-2 に、利用者を「Claude Code 経路。Serena は v0.1 後」に改める
- 2 章・3 章: CLI を `lsp-det -- <上流コマンド>` のみにする（D-11）
- 4.1〜4.4: 上流側と下流側の構造（D-1〜D-12）で書き直す。ゲート判定表から `dead` 行と `error` / `dead` のエラーコード論点を落とし、`warning` の写像を 5.1 に移す。4.4 の非常口を削除する
- 4.5: capability 注入を無条件に改める（D-3）
- 5 章: 写像の選択（`serverInfo.name`）、版の範囲（D-5）、`warning` の写像（D-6）を追加する
- 6 章: 下流側の準拠テストを追加する（D-8）
- 8 章: マイルストーンを E-1・E-2 に合わせる。M1 の日常稼働は観測手段（A-4）として位置づけ直す

### CLAUDE.md

- 「拡張 S」「ゲート」の記述を本 ADR の用語と構造に合わせる
- 未決事項「透過中のゲートの追跡対象」は D-1 で決着（下流側は境界の上の状態を読む）

### 実装

- `dead` の送出を削除し、上流消失時は保留分へのエラー応答と終了に改める（D-9）
- `--adapter` を `serverInfo.name` による選択に置き換え、capability 注入を無条件にする（D-2・D-3）。写像に版の範囲を持たせる（D-5）
- rust-analyzer の写像で「ワークスペース未発見」を `error` に写す（D-6）
- 下流側（保留・キャンセル・`shutdown` 時のエラー応答）を実装し、非常口は実装しない（D-7・D-9・D-10）
- 下流側の準拠テストスイートを追加する（D-8）
- 準拠テストの被験者から `dead` の検証を外す

### 上流提案への影響

「中継層でしか出せない値がある」という主張（ADR 0003、ADR 0008）は取り下げる。提案は「サーバーの義務」の層だけで成立し、観測者が合成する `unknown` は付録として添える。
