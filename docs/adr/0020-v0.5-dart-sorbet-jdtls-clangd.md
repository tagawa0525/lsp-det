# ADR 0020: 0.5.0 は固まった語彙に Dart、Sorbet、jdtls、clangd を当てる

- 日付: 2026-09-06
- 状態: 採用
- 関連: [ADR 0019](0019-v0.4-corpus-and-counterexamples.md) 決定 A-2（0.5.0 の範囲）・C（検証の段階）・G（観測者の注入）、[ADR 0018](0018-external-review-2026-09.md) 決定 A-3（仕様 10 章の Dart / Sorbet の行）・C・D、[ADR 0009](0009-success-criterion-and-two-sided-reference.md) 決定 C-4（時間判定の排除）・D-5（保証は測った版に）、[research/dart-and-sorbet-readiness-vocabulary.md](../research/dart-and-sorbet-readiness-vocabulary.md)、[research/readiness-vocabulary-corpus.md](../research/readiness-vocabulary-corpus.md)

## 経緯

0.4.0（ADR 0019）でコーパスの反例 11 件を実サーバーに当て、語彙は 4 値のまま動かなかった。観測者の規則も 3 つ（決定 G）で足り、追加で分かったのは「版が語彙に現れないサーバーには保証を宣言しない」「観測者は信号の有効化は注入するが初期化や起動フラグは肩代わりしない」の 2 つで、いずれも仕様 8 章の範囲に収まった。

ADR 0019 決定 A-2 は、固まった語彙に易しい 4 サーバー（Dart analysis server、Sorbet、jdtls、clangd）を当てるのを 0.5.0 とし、着手時に別の ADR で範囲を書くとした。本 ADR がそれである。4 つはいずれも仕様 10 章に「見込み」の行があり（Dart と Sorbet は ADR 0018 決定 A-3 で一次資料から、jdtls と clangd は v0.1 から）、0.5.0 は見込みを実測で置き換える。

## 決定

### A. 範囲

1. **0.5.0** は Dart analysis server、Sorbet、jdtls、clangd の 4 つに ADR 0019 決定 C の段階（`flake.nix` → 実測記録 → 写像を RED → GREEN → REFACTOR → 実サーバーの結合テスト → 保証の宣言）を当てる。順序は Dart → Sorbet → jdtls → clangd。写像を書けない結論（`unknown` が正直）も結果として記録する
2. 語彙と観測者の規則は動かさない前提で始める。動かす必要が出たら、0.4.0 と同じく報告して止まり、ADR を書いてから既存の写像・準拠テスト・fork のパッチを追従させる
3. 外部へのアクションは 0.5.0 の後（ADR 0018 決定 D）。4 サーバーで見つかった上流への提案は `docs/upstream-submissions.md` に行を足すだけにする

### B. 入手

いずれも `flake.nix` の `servers` に足す。版の固定はそこ（ADR 0019 決定 D）。

| サーバー             | 入手                                                                                                                                                      | 版        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| Dart analysis server | nixpkgs `dart`（`dart language-server`）                                                                                                                  | 3.13.0    |
| Sorbet               | nixpkgs にない。rubygems の `sorbet-static` の x86_64-linux の prebuilt（`libexec/sorbet`。glibc 以外に依存しない）を `fetchurl` で取り derivation にする | 0.6.13485 |
| jdtls                | nixpkgs `jdt-language-server`                                                                                                                             | 1.60.0    |
| clangd               | nixpkgs `clang-tools`                                                                                                                                     | 21.1.8    |

Sorbet の derivation は x86_64-linux に限る。他の OS の開発環境では `servers` の devShell に入らないが、CI は実サーバーを回さないので影響はない。aarch64-linux と universal-darwin の prebuilt も rubygems にあるので、要るときに `system` で分岐させる。

| サーバー | 名乗り                                                                                      | 見込みの写像                                                                                                                                                                                                                                                                                                                    | 確かめること                                                                                                                                                                                                                                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dart     | `serverInfo` "Dart SDK LSP Analysis Server"、版あり（実測済み）                             | `$/progress`（token `ANALYZING`、title "Analyzing…"）の begin で `indexing`、end で `ready`。rust-analyzer の `quiescent` と同型で、再解析も同じ対。health は信号がなく `unknown`                                                                                                                                               | 2 ファイルの fixture では end の前でも完全だった。索引に観測できる時間を要する規模（7.1 の前提）の fixture で、begin〜end の間の `references` が不完全か。token が解析のたびに `window/workDoneProgress/create` で作り直されるので、observer が create を毎回答えて追えるか                                                    |
| Sorbet   | `serverInfo` なし（実測済み）。名乗りは `sorbet/showOperation` そのもの。版は語彙に現れない | `sorbet/showOperation` の `Indexing` / `SlowPathBlocking` / `SlowPathNonBlocking` の start で `indexing`、未完了の操作がなくなった end で `ready`。操作は入れ子になる（SlowPathBlocking の中に Indexing。実測済み）ので数える。`References` 等の要求に伴う操作と `FastPath` は状態にしない。health は文書に信号がなく `unknown` | `SlowPathNonBlocking` の間の `references` が文書のとおり不完全か（文書は Idle でしか答えないと言う）。`FastPath`（開いている文書の編集の後の差分型検査）の間に他ファイルの `references` が古いか。古ければ `FastPath` も `indexing` に写す（仕様 6 章 3 項）。`--disable-watchman` で `didChangeWatchedFiles` が織り込まれるか |

### D. Sorbet の opt-in は `initializationOptions` に、lsp-det が起動したコマンドが Sorbet のときだけ注入する

`sorbet/showOperation` はクライアントが `initializationOptions.supportsOperationNotifications: true` を渡したときしか送られない。信号の有効化なので観測者が注入してよい（ADR 0019 決定 G。初期化や起動フラグの肩代わりではない）。

注入の位置は `window.workDoneProgress` と同じ `initialize` の書き換えだが、`initializationOptions` は capability と違ってサーバーごとに意味が決まる自由な値で、全上流に一律に足すと知らない設定を警告するサーバー（gopls は未知の設定を `window/showMessage`（type 1 "Invalid settings: … unexpected setting"）で報告する。実測済み）に副作用が出る。そこで、lsp-det 自身が起動した上流のコマンド名（argv の先頭の basename が `sorbet` または `srb`）のときだけ注入する。これは推測ではなく lsp-det が知っている事実で、外れても写像が選ばれず両軸 `unknown` になるだけで嘘にはならない。写像の選択はこれまでどおり名乗り（`sorbet/showOperation`）で行い、コマンド名は注入にしか使わない。

### E. 版が語彙に現れないサーバーには保証を宣言しない

0.4.0 の規則（ADR 0019 追補の M12 以降）を引き継ぐ。Sorbet は `serverInfo` を返さず、`sorbet/showOperation` にも版がないので、7.2 / 7.3 が通っても `guarantees()` は `{}`。`InitializeResult.serverInfo` を返す PR を提出候補にする。jdtls と clangd は実測で決める。

### F. マイルストーン

| M   | サーバー | 段階                                                                      |
| --- | -------- | ------------------------------------------------------------------------- |
| M21 | Dart     | 決定 C の全段階。索引に時間を要する fixture を `tests/support` に生成する |
| M22 | Sorbet   | 同上。決定 D の注入を含む                                                 |
| M23 | jdtls    | 同上                                                                      |
| M24 | clangd   | 同上。仕様 10 章と 8.2 の例の訂正はユーザーの承認の後                     |

各 M は 1 つの PR。機械的な段階（写像・テスト・文書の反映）は実測記録を元に Sonnet に委ね、実測と設計、rebase と確認は Fable が行う（0.4.0 の M17、M19、M20 と同じ）。

### 却下した案

| 案                                                                             | 却下理由                                                                                                                      |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `supportsOperationNotifications` を全上流の `initializationOptions` に注入する | 決定 D。`initializationOptions` はサーバーごとの自由な値で、知らない設定を警告するサーバーに副作用が出る                      |
| コマンド名で写像を選ぶ                                                         | 名乗りで選ぶ方針（ADR 0011）を崩す。コマンド名は注入にしか使わない                                                            |
| Sorbet は `srb tc --lsp`（Ruby の gem のラッパー）で起動する                   | Ruby の環境が要り、prebuilt の `sorbet` と同じバイナリを呼ぶだけ。devShell には `sorbet` を置く                               |
| clangd は 10 章のとおり信号なしとして測らない                                  | LLVM のソースに `$/progress` があり、測らずに「なし」を書き続けるのは ADR 0018 決定 C（サーバー自身の資料で確かめる）に反する |
| clangd の 10 章の行を実測の前に直す                                            | 仕様の書き換えは実測とユーザーの承認の後                                                                                      |
| 4 つをまとめて 1 つの PR にする                                                | 0.4.0 と同じく 1 サーバー 1 PR。実測記録がレビューの単位                                                                      |

## 追補（2026-09-06）: 結果

- M21 Dart: 済み（[research/dart-readiness-measurement.md](../research/dart-readiness-measurement.md)）。見込みの写像のとおり、`$/progress`（token `ANALYZING`）の begin で `indexing`、end で `ready`。確かめること「索引に観測できる時間を要する規模の fixture で begin〜end の間の `references` が不完全か」への答えは「不完全にならない」: 401 ファイルの被験体で実測すると、サーバー自身が要求を依存する解析の完了まで待たせる（`requireResolvedUnit`）ため、観測者の保留がなくても空応答・部分応答は出ない。したがって `didChange` / `didChangeWatchedFiles` からの先読みは要らず、`observe_client` は実装しない。`workspace/didChangeWatchedFiles` の代行（ADR 0015）にはサーバーが "Unknown method" の `window/showMessage`（type 1）を返すが、取り込みはサーバー自身のファイル監視で成り立つ（副作用は表示だけ）。health の信号はなく `unknown` にとどまる。3.13.0 に `coverage: {scope: "workspace", incomplete: {}}` と `freshness: {fileChanges: ["Created", "Changed", "Deleted"]}` を宣言する。実サーバー結合テスト 7.1〜7.3 は 3 回連続で通した
- M22 Sorbet: 済み（[research/sorbet-readiness-measurement.md](../research/sorbet-readiness-measurement.md)）。見込みの写像のとおり、要求に伴わない操作（`Indexing`、`SlowPathBlocking`、`SlowPathNonBlocking`）の start/end を入れ子ぶん数え、未完了の操作がなくなった end で `ready`。`serverInfo` がなく名乗りは `sorbet/showOperation` の通知そのもの（版はどこにも現れない）ので `guarantees()` は常に `{}`。確かめること「`SlowPathNonBlocking` の間の `references` が Idle でしか答えないという文書のとおり不完全か」への答えは「文書のとおり、保留される」: 600 ファイルの被験体で開いているファイルに `didChange` すると `SlowPathBlocking`（`Indexing` を入れ子）→ `SlowPathNonBlocking` が走り、その間に送った `references` は `SlowPathNonBlocking` の end まで答えが返らない（研究記録の走行 2、実サーバー結合テスト 7.3 の 1 で確認）。「`FastPath` の間に他ファイルの `references` が古いか」は、この被験体の編集（メソッド呼び出しの追加）では一度も `FastPath` が観測されず（研究記録・本結合テストとも同じ）、答えられない。「`--disable-watchman` で `didChangeWatchedFiles` が織り込まれるか」への答えは「織り込まれない」: Sorbet は登録も読みもしないので、代行の通知は届いても無視される。決定 D の注入は、lsp-det が起動したコマンドの basename が `sorbet` / `srb` のときだけ `initializationOptions.supportsOperationNotifications: true` を足す形で実装した（コマンド名は注入にのみ使い、写像の選択は名乗りのまま）。実サーバー結合テストは `--disable-watchman` で 7.1・7.2・7.3 の 1 のみを当て（2〜4 は watchman の daemon と既存の `watch-project` を要し、環境にない）、3 回連続で通した。`references` は `includeDeclaration: false` でも宣言部位（`def self.target` 自体）を含めて返す（実測）
- M23 jdtls: 済み（[research/jdtls-readiness-measurement.md](../research/jdtls-readiness-measurement.md)）。見込みの写像のとおり `language/status` の `ServiceReady` で `ready`。確かめること「`ServiceReady` の時点で `references` が完全か、それとも `ProjectStatus` や `$/progress` の end まで待つ必要があるか」への答えは「`ServiceReady` で足りる」: JDT の検索自体が索引の完了を `WAIT_UNTIL_READY_TO_SEARCH` で待つ（`BasicSearchEngine.findMatches`）ため、201 クラスの被験体で `ServiceReady` の前に送った `references` も完全に答えた。`$/progress`（"Building" 等）は索引ではなく診断用のコンパイルで、写すと完全な結果を遅らせるだけなので写像に使わない。「`pom.xml` の変更で再インポートしたとき信号が再送されるか」は、この被験体が Eclipse の記述（`.project`/`.classpath`）で Maven を使わないため未確認のまま。代わりに測れた `.classpath` の変更では `ProjectStatus` は再送されなかった（8 秒待っても来ない）。「`ProjectStatus` の message の語彙」は "OK" と、`type: "Error"` の 2 つを確認。"WARNING" はソースにある語彙だが、`reportProjectsStatus` がビルドのマーカー付けより先に呼ばれるため実測した被験体では一度も出ず、壊れた classpath はプロジェクト自身の URI への `publishDiagnostics`（severity 1）に現れた。これも health の `warning` とし、その URI の診断が空になれば直前の `ProjectStatus`/`Error` に戻す。1.60.0-SNAPSHOT に `coverage: {scope: "workspace", incomplete: {}}` と `freshness: {fileChanges: ["Created", "Changed", "Deleted"]}` を宣言する。実サーバー結合テスト 7.1〜7.3 は 3 回連続で通した
