# ADR 索引

ADR は採用後に本文を書き換えない。決定が覆ったときは新しい ADR を書き、古い ADR は状態行に「廃止」と置き換え先を記す。本索引は各 ADR について**生きている決定だけ**を列挙する。廃止された決定を読む必要はない。経緯を知りたいときだけ本文に当たる。

| ADR                                                                              | 主題                                                                                      | 生きている決定                                                                                                                                                                                                                                                                                                                                                                        | 廃止・置き換え                                                                              |

| [0001](0001-tool-first-readiness-gate.md)                                        | ツール先行と v0.1 の絞り込み                                                              | v0.1 はサーバー状態のみで、宣言範囲と起動方法の宣言は凍結（決定 2）。写像はサーバー別（決定 4）。起動指定は argv 完結で設定ファイルを持たない（決定 6）                                                                                                                                                                                                                               | 決定 1（成功基準）、決定 3 のタイムアウト、決定 5 の選定理由、決定 6 の `--adapter` は 0009 |
| [0002](0002-extension-b-surface-in-v01.md)                                       | サーバー状態のリクエストと通知を v0.1 で提供する                                          | 下流が宣言していれば下流側は待たない（決定 3）。呼ぶ側は偽クライアントで用意する（決定 5）                                                                                                                                                                                                                                                                                            | 決定 1・2 は 0003 が改名・廃止。決定 4 の位置づけは 0009                                    |
| [0003](0003-extension-s-zero-based.md)                                           | readiness をサーバー状態（health + readiness）に再定義                                    | 2 軸の `ServerState`（決定 1）。鮮度は契約文言で保証し因果トークンは将来（決定 3）。診断の完了は予約のみ（決定 4）。`$partial` と `completeMethods` の廃止（決定 5）。「3 点」の枠の廃止（決定 6）。仕様が第一の成果物（決定 7）                                                                                                                                                      | 決定 2（`dead` の代理送出）は 0009                                                          |
| [0004](0004-spec-grilling.md)                                                    | 仕様精査で確定した判断                                                                    | 2 軸は独立（決定 1）。`coverage` / `freshness` は capability のオプション（決定 3 の構造。名前は 0013 が改名）。メソッド名は受理まで `experimental/`（決定 4）。クライアント宣言は「自分で判断する」意思表示（決定 5）。準拠テストは独立成果物（決定 7）                                                                                                                              | 決定 2（`dead` を残す）、決定 3 の「グレード」の語、決定 6（`--gate-mode`）は 0009          |

| [0006](0006-external-review-fixes.md)                                            | 外部レビューによる補正                                                                    | ADR 0001 と 0003 の優先関係（決定 1）。freshness テストはクロスファイル必須（決定 2）。`experimental/serverState` の命名維持と `serverStatus` 流用の却下（決定 4）                                                                                                                                                                                                                    | 決定 3（通常編集のフラップ）は 0007 が前提を否定。決定 5（Linux のみ）は 0012               |
| [0007](0007-quiescent-flap-measured.md)                                          | 通常編集で quiescent は往復しない                                                         | 全部。フラップ対策は実装しない。測定値を一般化しない。推論を確認済みと書かない                                                                                                                                                                                                                                                                                                        | なし                                                                                        |
| [0008](0008-unknown-readiness-and-health-terminates-waiting.md)                  | 両軸の `unknown` と `health` による待機終了                                               | `readiness` と `health` に観測者専用の `unknown`（決定 A、追補 C-1 の `unknown` 部分）。失敗は `health` で表し、`error` なら待たない（決定 B-1〜B-3）。保証は `health` が壊れていないときのみ（追補 C-2）。アダプタありも最初の信号まで `health` は `unknown`（追補 E）                                                                                                               | 決定 A-5、決定 B-4（タイムアウト）、追補 C-1 と C-5 の `dead`、追補 D（透過）は 0009        |

| [0010](0010-python-typescript-mappings-for-client-adoption.md)                   | v0.2 は Python と TypeScript の写像を足し、Serena を下流の被験者にする                    | 全部。v0.1 は現在の main で完了。M5 pyright（信号は 0011 が正）、M6 typescript-language-server、M7 Serena 統合。時間判定の禁止と保証の宣言方法を引き継ぐ。jdtls・clangd・宣言範囲は範囲外。上流 issue は並行可（README と英訳が前提）                                                                                                                                                 |                                                                                             |
| [0011](0011-pyright-identity-from-startup-log-and-readiness-from-enumeration.md) | `serverInfo` のないサーバーの名乗りと pyright の readiness                                | 全部。`serverInfo` がなければ起動時の `window/logMessage` の名乗りで写像を選ぶ（`initialize` 応答前でも可、後から `serverInfo` が来れば選び直す）。pyright の readiness はファイル列挙完了のログで、フォルダ数ぶん待つ。health は `unknown`。`$/progress` は読まない。pyright 本体に `serverInfo` を足す PR を出す                                                                    |                                                                                             |
| [0012](0012-macos-and-windows-support.md)                                        | macOS と Windows に対応する                                                               | 全部。対応 OS は Linux・macOS・Windows。プロセス寿命の 2 経路（クライアント死→lsp-det 終了、lsp-det 死→上流終了）は OS ごとの機構（Linux: `PR_SET_PDEATHSIG`、macOS: `kqueue` の `EVFILT_PROC`、Windows: 親ハンドル待ちと Job Object）。時間判定と依存の追加はしない。macOS の上流の追従は stdin の EOF に委ねる。CI は 3 OS で回し、`v*` タグで各 OS のバイナリを Release に添付する |                                                                                             |
| [0013](0013-coverage-instead-of-completeness.md)                                 | `completeness` を `coverage` に改名し、`workspace/symbol` を保証から外す                  | 全部。保証の定義は「ワークスペース全体のインデックスに基づき、後から結果が増えない」まで。`workspace/symbol` は保留の対象には残し `coverage` の対象から外す（rust-analyzer 128、gopls 100 で黙って打ち切る）。改名は仕様・設計・実装・fork のパッチに及ぶ                                                                                                                             |                                                                                             |
| [0014](0014-freshness-covers-watched-file-changes.md)                            | `freshness` の対象に受信した `workspace/didChangeWatchedFiles` を加える                   | 全部。約束は知らされた変更まで（サーバー自身の監視は対象外）。7.3 に第 2 のテスト（ディスク上の変更と新規ファイル。Deleted は含めない）。クライアントの欠落の代行は 0015                                                                                                                                                                                                              |                                                                                             |
| [0015](0015-downstream-stand-ins-for-watched-files-and-duplicate-didopen.md)     | 下流側が `didChangeWatchedFiles` を代行し、重複した `didOpen` を `didChange` に書き換える | 全部。代行は capability を宣言せず通知も送らないクライアントにだけ、7.0 の一覧のリクエストを引き金に `git ls-files` の一覧の mtime を比べて行う。写像は関与せず、git 管理外では行わない。重複 `didOpen` の書き換えは全上流。仕様には触れない（設計 4.3）                                                                                                                              |                                                                                             |
