# readiness の語彙の机上コーパス: Serena の 70 サーバーを本プロトコルに写す

ADR 0018 決定 A-5、ADR 0019 M8。外部レビュー（[external-review-2026-09.md](external-review-2026-09.md) §6）の提案「Serena の 30 言語表を lsp-det の語彙に写し、全部埋まれば readiness の語彙は硬くしてよい。埋まらない行が硬くしてはいけない箇所の一覧になる」を実行した記録。上流提案の添付資料であり、ADR 0019 決定 B の「実サーバーで検証する言語」を選ぶ根拠でもある。

## 方法

- 出発点は [serena-solidlsp.md](serena-solidlsp.md) 1.2 の表（Serena `7fcbca7e` の `src/solidlsp/language_servers/`、専用クラス 44 + 「その他即時系」26 = 70 サーバー）
- **各行はサーバー自身の文書とソースで確かめた**（ADR 0018 決定 C。Serena の待ち方から信号を推測しない）。GitHub のソース（`gh api` / `gh search code`）と公式文書を出典に記し、到達できなかったものは「未確認」と書く
- 下書きは 4 群に分けて Sonnet に任せ（2026-09-06）、主要な主張 8 件を私が一次資料で抜き取り検証した（末尾）。写像と「疑問」の判定は各行の出典に基づく
- 「写像に疑問」は、時間を使わないと `ready` を言えない、進捗が per-request / per-file で単一の readiness に乗らない、相方サーバーに依存する、ポーリングでしか取れない、信号が設定で無効、または信号がなく Serena の sleep が実在の穴を示唆する、のいずれか。「なし」は時間なしで写像できるか、信号がないことに疑いがない（`unknown` で正しい）か、索引自体がない（`ready` で正しい）

## 要約

70 行すべてが `initializing` / `indexing` / `ready` / `unknown` のどれかに写り、**新しい値を要する行はなかった**。「疑問あり」38 行の中身は語彙の欠けではなく、信号の構造（複数トークン、per-request、設定依存）と、信号の不在（`unknown` で正しい）である。

語彙への含意:

- readiness の 4 値は 70 サーバーの信号を全部受け止めた。硬くしてよい
- 観測者の規則として要るのは新しい値ではなく、(1) 複数トークンは未完了がなくなったら `ready`、(2) per-request / per-file の進捗は readiness に写さない、(3) opt-in の信号は観測者が有効化を注入してよい、の 3 つ。いずれも 8 章の合成の規則の範囲で、サーバーの義務（3〜7 章）は変わらない
- 時間でしか終わりを言えないサーバー（Metals）は `unknown` で正しく、時間判定を持ち込まない（ADR 0019 決定 C）
- health の信号を持つのは rust-analyzer、gopls、jdtls、tsls（クラッシュ）、clojure-lsp、phpactor（watcher 死亡）、Roslyn（トースト一度きり）程度で、大半は `unknown`。health の軸は「あれば写す」で足りる
